# Контракт API — вики «Арвари»

Что фронтенд ожидает от бэкенда. Документ описывает **реально используемые**
поля: всё перечисленное здесь читается кодом фронтенда, ничего «на будущее» нет.

> **Статус.** Бэкенд реализован — ASP.NET Core (C#) в папке `backend/`, база
> SQLite. Все ручки ниже работают и проверены сквозным тестом. Инструкция
> запуска — в `backend/README.md`.

Фронтенд ходит в API только через `src/api/*`. Пока переменная `VITE_API_URL`
пуста, он работает на локальных данных (мок-режим) — можно разрабатывать
параллельно. Как только адрес задан, включается HTTP.

- Базовый адрес: `VITE_API_URL` (например `https://api.arvari.example/v1`)
- Формат: JSON, UTF-8
- **CORS**: нужны `GET, POST, PUT, DELETE, OPTIONS` и заголовки
  `Content-Type`, `Authorization`

---

## Авторизация

Роль одна — **Мастер** (хранитель мира). Читать может кто угодно без токена;
любая правка требует токена.

### `POST /auth/login`

```jsonc
// запрос
{ "name": "Мастер", "passphrase": "…" }

// ответ 200
{ "token": "…", "name": "Мастер" }
```

Неверный ключ → **401** с телом `{ "message": "текст для пользователя" }`
(фронтенд покажет это сообщение как есть).

Дальше токен уходит в заголовке:

```
Authorization: Bearer <token>
```

> **Важно.** Фронтенд лишь прячет кнопки — защиты в нём нет. Любой посетитель
> может подделать состояние в браузере, поэтому **каждая** правящая ручка
> обязана проверять токен на сервере. Если ответ приходит `401`/`403`,
> фронтенд стирает токен и просит войти заново.

## Статьи

### `GET /articles`

Все статьи для каталога, поиска и вики-ссылок. Возвращает массив `Article`.

Сейчас фронтенд фильтрует, ищет и разбивает на страницы у себя. На объёме
~400 статей это приемлемо; если планируется рост, обсудим серверные
`?category=&subcategory=&q=&page=`.

### `GET /articles/{slug}` → `Article`

Несуществующий slug → **404** (фронтенд покажет страницу «Статья не найдена»).

### `POST /articles` (нужен токен) → `Article`

Создание. Тело — `Article` без серверных полей (`views`, `edits`, `date`).

### `PUT /articles/{slug}` (нужен токен) → `Article`

Правка. **Slug в адресе не меняется**, даже если изменилось название —
иначе ломаются вики-ссылки `[[…]]` из других статей.

### `DELETE /articles/{slug}` (нужен токен) → **204**

**Черновики.** У статьи есть поле `draft` (bool). `GET /articles` без токена
отдаёт только опубликованные; с токеном Мастера — включая черновики.
`GET /articles/{slug}` для черновика без токена → **404**. POST/PUT принимают
`draft` в теле (по умолчанию false; PUT сохраняет прежнее, если не передан).

### `POST /articles/{slug}/view` → `{ views }`

Публичная (без токена). Каждый заход на статью увеличивает счётчик просмотров
на 1 и возвращает новое значение. По этому полю считается блок «Популярные
статьи» на главной. Несуществующий slug → **404**.

## Модель `Article`

```jsonc
{
  // ---- обязательные ----
  "slug": "istmuslend",            // адрес статьи, латиница; см. «Slug» ниже
  "title": "Истмусленд",
  "category": "Государства",       // ровно одна из 9 категорий (список ниже)
  "excerpt": "Морская монархия…",  // 1–2 предложения для карточки в каталоге

  // ---- опциональные ----
  "subcategory": "Города",         // только для категорий с подкатегориями
  "tag": "Королевство Ветров",     // подпись на карточке; если нет — берётся category
  "lead": "Полуостровное госуда…", // курсив под заголовком; если нет — excerpt
  "heroCaption": "Аэрондиль, столица", // подпись под широкой картинкой сверху;
                                       // если поля нет — картинка не показывается
  "markdown": "## География\n…",   // тело статьи, разметка Obsidian (см. ниже)

  "cover": {
    "image": "/uploads/Истмусленд пейзаж.png",
    "position": "50% 20%"          // точка фокуса при обрезке (см. «Обложки»)
  },

  "infobox": {                     // карточка-справка справа от текста
    "image": "/uploads/portret.png",
    "rows": [
      { "label": "Столица", "value": "Аэрондиль" }
    ]
  },

  "related": ["aerondil", "vestrond"],  // slug'и связанных статей

  // ---- заполняет сервер ----
  "date": "2026-07-16",            // ISO-дата, для сортировки «по дате»
  "views": 512,                    // для сортировки «по популярности»
  "edits": 8,
  "updatedLabel": "Обновлено сегодня"  // человекочитаемо; можно не присылать
}
```

Поля `blocks` и `userCreated` — внутренние для фронтенда, присылать не нужно.

### Категории

Строго эти девять (значение поля `category`):

`Персонажи`, `Локации`, `События`, `Существа`, `Фракции`, `Артефакты`,
`Легенды`, `Боги`, `Государства`

Подкатегории есть у трёх:

- **Персонажи**: Правители, Персонажи игроков, Торговцы и ремесленники,
  Легендарные личности, Жрецы и служители, Наёмники и воины,
  Учёные и мудрецы, Простой люд
- **Локации**: Города, Деревни, Замки, Леса, Водоёмы, Пещеры, Святые места
- **Артефакты**: Амулеты, Доспехи, Оружие, Кольца, Музыкальные инструменты,
  Щиты, Другое

### Slug

Владелец — **сервер**. Фронтенд умеет предлагать вариант (транслитерация
названия), но уникальность и разрешение коллизий за бэкендом: две статьи с
одинаковым названием — обычное дело.

Ключевой момент: вики-ссылка `[[Аэрондиль]]` превращается на фронтенде в slug
той же транслитерацией. Чтобы ссылки находили цель, серверный slug для
названия «Аэрондиль» должен быть `aerondil`.

Алгоритм — `src/lib/slug.js`, правила закреплены тестами (`slug.test.js`):

- кириллица → латиница; `ж`→`zh`, `ц`→`ts`, `ч`→`ch`, `ш`→`sh`, `щ`→`shch`,
  `ю`→`yu`, `я`→`ya`, `ё`→`e`
- **`й` и `ы` → `y`** (например «Февралий» → `fevraliy`)
- `ь` и `ъ` выбрасываются («Дань» → `dan`)
- всё, кроме латиницы и цифр, схлопывается в один дефис; по краям дефисов нет

Если бэкенд генерирует slug иначе, ссылки перестанут находить статьи — тогда
нужен либо общий алгоритм, либо поиск по названию: `GET /articles?title=…`.

### Тело статьи (`markdown`)

Разметка Obsidian, тексты приходят из хранилища Мастера как есть. Фронтенд
рендерит сам, обработка на сервере не нужна. Поддерживается:

| Разметка | Значение |
|---|---|
| `[[Название]]` | ссылка на статью |
| `[[Название\|текст]]` | ссылка с другим текстом |
| `![[файл.png]]` | картинка (`\|300` — ширина) |
| `# … ######` | заголовки (из `##`/`###` строится оглавление) |
| `**жирный**`, `_курсив_`, `***оба***` | начертание |
| `> цитата`, `- список`, `1. список`, `---` | блоки |
| `---` … `---` в начале | frontmatter (`tags` и т.п.), скрывается |

Ссылка на несуществующую статью — не ошибка: фронтенд подсветит её красным
пунктиром. Это нормальный рабочий режим вики.

### Обложки

`cover.position` — точка фокуса вида `"50% 20%"` (X% Y% от левого верхнего
угла). Нужна потому, что обложка обрезается под разные форматы карточек, и без
неё у вертикальных портретов отрезает лицо. Мастер задаёт её мышью в редакторе.
Сервер просто хранит строку. Если поля нет — фронтенд берёт центр.

## Вестники (новости на главной)

### `GET /news` → `NewsItem[]`
### `PUT /news` (нужен токен) → `NewsItem[]`

Список приходит и сохраняется целиком, в порядке отображения (первый — самый
свежий).

```jsonc
{

  "blurb": "Храмы всех пяти государств сообщают…"
}
```

## Хронология

### `GET /chronology` → `Epoch[]`
### `PUT /chronology` (нужен токен) → `Epoch[]`

Тоже целиком, порядок эпох = порядок прокрутки.

```jsonc
{
  "index": 0,
  "label": "Эпоха I · Тёмные Века",       // в шапке при прокрутке
  "kicker": "Эпоха I · 0–600 гг.",        // над заголовком
  "title": "Возрождение / Тёмные Века",
  "subtitle": "600 лет восстановления",
  "accent": "var(--chrono-accent-1)",     // одно из 6 значений, см. ниже
  "events": [
    { "year": "600 г.", "title": "Явление Длани", "text": "Боги являются…" }
  ]
}
```

`accent` задаёт и цвет акцентов, и фон эпохи. Допустимы ровно шесть строк:
`var(--chrono-accent-1)` … `var(--chrono-accent-6)` (серый, бронза, багровый,
фиолетовый, зелёный, янтарь). Хранить как есть.

## Предложка (идеи от игроков)

### `POST /suggestions` → `Suggestion` (без токена — шлёт любой)

```jsonc
// тело запроса
{ "author": "Имя или пусто", "kind": "Идея", "text": "Текст предложения" }
```

`kind` — одно из: `Идея`, `Новая статья`, `Правка`, `Ошибка на сайте`, `Другое`.
`text` обязателен, `author` может быть пустым (аноним).

### `GET /suggestions` (нужен токен) → `Suggestion[]`

Список для Мастера, новые сверху.

### `PATCH /suggestions/{id}` (нужен токен) → **204**

```jsonc
{ "read": true }   // отметить прочитанным / снять отметку
```

### `DELETE /suggestions/{id}` (нужен токен) → **204**

Модель `Suggestion`:

```jsonc
{
  "id": "s-…",
  "author": "Имя или пусто",
  "kind": "Идея",
  "text": "Текст предложения",
  "createdAt": "2026-07-23T12:00:00Z",
  "read": false
}
```

В мок-режиме предложения лежат в localStorage браузера отправителя, поэтому до
Мастера на другом устройстве не долетают — это лишь демонстрация. Реальную
доставку обеспечивает сервер.

## Загрузка изображений

### `POST /uploads` (нужен токен, `multipart/form-data`, поле `file`)

```jsonc
// ответ 200
{ "url": "/uploads/новый-арт.png" }
```

Сейчас в мок-режиме выбранная обложка кодируется в строку и кладётся в
хранилище браузера — на второй-третьей картинке оно переполняется. Это первое,
что нужно заменить настоящей загрузкой.

Просьба на стороне сервера: ужимать оригиналы. Арты по 3 МБ — норма для
исходников, но столько же качает каждый посетитель.

## Ошибки

Единый формат, фронтенд показывает `message` пользователю:

```jsonc
{ "message": "Понятный человеку текст" }
```

| Код | Когда | Что делает фронтенд |
|---|---|---|
| 400 | плохие данные | показывает `message` |
| 401 / 403 | нет или истёк токен | стирает токен, просит войти |
| 404 | нет статьи | страница «Статья не найдена» |
| 5xx | сбой сервера | показывает `message`, данные не теряет |

## Порядок подключения

1. Поднять `GET /articles`, `/news`, `/chronology` — только чтение.
2. Задать `VITE_API_URL` в `.env` фронтенда → он переключится на HTTP.
3. Добавить `POST /auth/login` и правящие ручки.
4. Убрать из фронтенда мок-режим: ветки `isMockMode` в `src/api/*`
   и слово-ключ из `src/api/auth.js`.

Шаги 1–2 можно делать, не трогая фронтенд: `src/api/content.js` уже умеет
ходить в три ручки чтения.
