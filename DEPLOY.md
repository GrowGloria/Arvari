# Развёртывание «Арвари» в интернете

Сайт состоит из двух частей — их размещают отдельно:

- **Фронтенд** (то, что видит посетитель) — статические файлы, хостинг бесплатный.
- **Бэкенд** (база со статьями + картинки) — нужен хостинг с **постоянным диском**,
  обычно от ~5 $/мес.

Рекомендуемая связка: **Railway** для бэкенда, **Vercel** для фронтенда.
Оба разворачиваются прямо из GitHub-репозитория.

> Аккаунты, привязку почты/карты и клики в панелях делаете вы — за вас это
> сделать нельзя. Ниже — по шагам.

---

## Порядок важен

Бэкенд знает адрес фронта (для CORS), а фронт знает адрес бэка (`VITE_API_URL`).
Поэтому: **сначала бэкенд** → узнали его адрес → **потом фронт** → узнали адрес
фронта → дописали его бэкенду. Один раз туда-обратно.

---

## Шаг 1. Бэкенд на Railway

1. Зайдите на **railway.app**, войдите через GitHub.
2. **New Project → Deploy from GitHub repo** → выберите репозиторий `Arvari`.
3. В настройках сервиса задайте **Root Directory: `backend`** — тогда Railway
   соберёт по `backend/Dockerfile`.
4. **Variables** (переменные окружения) — добавьте:
   - `ARVARI_PASSPHRASE` — ваше слово-ключ для входа Мастера (замените дефолтное!).
   - `ARVARI_SECRET` — длинная случайная строка (например, 32+ символов). Держите
     её постоянной, иначе токены будут сбрасываться.
   - `ARVARI_CORS` — оставьте пустым пока (заполним на шаге 3).
   - `PORT` Railway задаёт сам — трогать не нужно.
5. **Volume** (постоянный диск): добавьте том, **Mount path: `/data`**. Без него
   база и картинки сотрутся при перезапуске.
6. Дождитесь сборки. Railway даст публичный адрес вида
   `https://arvari-production.up.railway.app` — это **адрес бэкенда**, запишите.
7. Проверьте: откройте `<адрес>/chronology` — должен вернуться JSON с эпохами.

## Шаг 2. Фронтенд на Vercel

1. Зайдите на **vercel.com**, войдите через GitHub.
2. **Add New → Project** → импортируйте репозиторий `Arvari`.
3. Framework определится как **Vite**. Root Directory — корень репозитория
   (там, где `package.json`). Build: `npm run build`, output: `dist`.
4. **Environment Variables** → добавьте:
   - `VITE_API_URL` = адрес бэкенда с шага 1 (например
     `https://arvari-production.up.railway.app`).
5. **Deploy**. Vercel даст адрес вида `https://arvari.vercel.app` — это **адрес
   сайта**, запишите.

## Шаг 3. Связать (CORS)

1. Вернитесь в Railway → Variables → впишите `ARVARI_CORS` = адрес сайта из
   шага 2 (например `https://arvari.vercel.app`). Несколько адресов — через запятую.
2. Railway перезапустит бэкенд. Готово.

---

## Проверка

Откройте адрес сайта с телефона. Зайдите в `/editor`, войдите словом-ключом
(`ARVARI_PASSPHRASE`), опубликуйте статью — она сохранится в базе и будет видна
с любого устройства.

## Какую ветку разворачивать

Работа лежит в ветке `frontend`. Либо влейте её PR в `main` и разворачивайте
`main`, либо в настройках Railway и Vercel выберите ветку `frontend`.

## Обновления

После `git push` в развёрнутую ветку Railway и Vercel **пересоберут сами**.
База и картинки на постоянном диске при этом сохраняются.

## Безопасность (обязательно перед публикацией)

- Смените `ARVARI_PASSPHRASE` с дефолтного «арвари» на свой.
- Задайте длинный случайный `ARVARI_SECRET` и не меняйте его.
- Эти значения — только в переменных окружения хостинга, **не в коде и не в git**.

## Заметки

- Картинки хранятся на диске бэкенда (`/data/uploads`). Vercel их не видит —
  они отдаются с адреса бэкенда, это нормально.
- SQLite тянет одного Мастера и умеренный трафик. Под серьёзный рост — переезд
  на PostgreSQL (в EF Core меняется провайдер и строка подключения).
- Альтернатива Railway с постоянным диском: **Fly.io** (мощнее, но через CLI).
  Альтернатива Vercel: **Cloudflare Pages** (тоже бесплатно).
